# Destructor：作用域、所有权与析构

[对应源码](../../../exercises/03_ticket_v1/11_destructor/src/lib.rs)

## 作用域结束与资源清理

绑定从声明处开始可用；离开其作用域时，仍由它拥有的值会被丢弃。Rust 会运行值的析构逻辑，并递归清理其拥有的字段资源。局部变量通常按声明的相反顺序析构。

`std::mem::drop(value)` 可提前丢弃一个拥有的值。它是接收值的普通函数；值被传入后，调用者不再拥有该值，不能继续使用它。

## 所有权转移也转移清理责任

把 `String` 按值传给函数，会把所有权和最终清理责任一起交给函数参数。参数离开作用域时负责析构；调用者原来的绑定已被移动，不能再使用。这样同一资源只由一个所有者负责清理，避免重复释放。

## 引用不拥有所指数据

引用只借用数据，不负责析构它指向的值。因此 `drop(&x)` 不会释放 `x`。共享引用如 `&i32` 实现了 `Copy`，所以把它传给 `drop` 会复制引用；原绑定仍可用。相反，`String` 不实现 `Copy`，`drop(s)` 会移动并销毁它，之后不能再使用 `s`。

Rust 的借用检查确保引用不会在所指数据失效后继续被安全地使用，从而避免悬垂引用。
