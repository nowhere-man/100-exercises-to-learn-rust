# Ownership：移动、资源释放与借用

[对应源码](../../../exercises/03_ticket_v1/06_ownership/src/lib.rs)

## 所有者负责资源的生命周期

所有者负责持有值，并在值不再需要时释放其资源。所有权可以转移，引用则让其他代码在不取得所有权的情况下访问值。

Rust 不依赖运行时垃圾回收器，而是通过所有权和编译时借用检查来防止释放后访问、重复释放等内存错误。这里的保证针对安全 Rust；不能把它扩大为任何 `unsafe` 代码都不会出错，也不代表绝对不会泄漏资源。

## 按值赋值不一定移动

**是否复制取决于类型是否实现 `Copy`，不能把所有赋值都理解为所有权转移。**

```rust
let a = 42;
let b = a; // 整数实现 Copy，a 和 b 都可继续使用

let s = String::from("hello");
let t = s; // String 没有实现 Copy，s 不可继续使用
```

整数、`bool` 等类型可以隐式复制；本题的 `Ticket` 和 `String` 按值赋值时移动。自定义结构体不是永远不能实现 `Copy`，但本题含有 `String` 字段，不能直接成为 `Copy` 类型。

函数按值接收参数也遵循这条规则。与 C++ 的被移动对象仍然存在不同，Rust 会禁止继续使用已移动的绑定，直到它被重新初始化。

## `self` 拿走对象，返回字段后释放剩余资源

```rust
pub fn status(self) -> String {
    self.status
}
```

对于这个非 `Copy` 的 `Ticket`，`ticket.status()` 可以理解为 `Ticket::status(ticket)`：整个对象被移动到局部参数 `self`。

1. 方法取得整个 `Ticket` 的所有权。
2. `status` 字段被移动给返回值，交给调用者。
3. 方法结束，局部参数退出作用域，剩下的 `title` 和 `description` 自动释放。

**“丢弃”是释放剩余字段的资源，不是释放已经返回的字符串。** 这类似 C++ 中按值参数离开作用域时析构；返回的字段已经移出，不随剩余字段一起销毁。因此不能在调用 `status()` 后再使用原来的 `ticket` 调用 `title()`。

## 借用让所有者保留对象

引用是访问已有值的凭证，不拥有被引用值的资源。

| 参数形式 | 对本题 Ticket 的含义 |
|---|---|
| `self` | 取得所有权，消耗调用者的对象 |
| `&self` | 共享借用，读取对象 |
| `&mut self` | 独占借用，读取和修改对象 |

```rust
pub fn title(&self) -> &String {
    &self.title
}
```

`&self` 借用整个对象，`-> &String` 返回字段的引用，`&self.title` 创建对字段的借用。所有者仍持有完整的 `Ticket`，因此可以连续调用三个读取方法。

只改成 `&self` 而仍返回 `self.title` 不行：共享借用不允许拿走字符串字段。编译器还会保证返回引用的有效期不超过它指向的数据，防止悬挂引用。

## 借用规则是共享或独占

对本题这种普通数据，**同一值可以被多个共享引用读取，或者被一个可变引用独占访问；不能同时存在冲突的借用。**

可变引用本身可以先读再写，所以“修改时不能读取”过于绝对。限制的是其他冲突访问，不是修改者自己的读取。共享借用仍需要使用时，所有者不能修改、移走或释放被借用的数据；独占借用活跃时，所有者也不能绕过引用直接进行冲突访问。

“只读锁 / 读写锁”仅是权限类比，不意味着运行时真的加锁。这些约束由编译器的借用检查器检查。

## 借用的有效期与 `&` 的位置

借用有效期由引用的实际使用决定，在简单的局部场景中通常到最后一次使用为止，不必持续到整个作用域结束。

```rust
let mut s = String::from("hello");
let r = &s;
println!("{r}"); // 最后一次使用 r
s.push('!');     // 借用已经结束，可以修改
```

`let r: &String = &s;` 中，类型前的 `&String` 表示引用类型，表达式中的 `&s` 表示借用操作。创建可变借用写 `&mut s`；普通局部值还需要用 `let mut s` 允许修改。
