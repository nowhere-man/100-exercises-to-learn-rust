# Rust 所有权、借用与生命周期

Rust 的内存管理主要建立在三个机制上：

1.  **所有权（Ownership）**：谁负责管理数据？
2.  **借用（Borrowing）**：如何在不转移所有权的情况下使用数据？
3.  **生命周期（Lifetime）**：引用可以安全地使用到什么时候？

------------------------------------------------------------------------

# 一、所有权（Ownership）

## 1. 为什么需要所有权？

在其他语言中，内存通常由垃圾回收机制或程序员管理。
+ `C`: 手动 malloc/free
+ `Modern C++`: RAII、智能指针
+ `Go`: 垃圾回收 GC

Rust 希望同时实现两个目标：
1. 不需要 GC，避免运行时垃圾回收开销。
2. 避免内存泄漏、悬垂指针、重复释放等问题。

为此，Rust 引入了所有权规则: 每块数据都有一个明确的所有者，由所有者负责管理这块数据的生命周期。


## 2. 所有权

Rust 的所有权有三个基本规则：
1. Rust 中每个值都有一个所有者（Owner）。
2. 一个值在同一时间只能有一个所有者。
3. 当所有者离开作用域时，值会被自动释放。


### 每个值都有一个所有者
```rust
fn main() {
    let s = String::from("hello");

    println!("{}", s);
}
```
这里：
- String::from("hello") 在堆上分配内存。
- s 是这个 String 的所有者。
- 当 main 函数结束时，s 离开作用域。
- Rust 自动释放 String 占用的堆内存。

### 所有权转移（Move）
```rust
fn main() {
    let s1 = String::from("hello");

    let s2 = s1;

    println!("{}", s2);

    // println!("{}", s1); // 编译错误
}
```
对于 `String` 这种没有实现 `Copy` 的类型，赋值操作会发生**Move（所有权转移）**。


为什么要这样设计？假设 s1 和 s2 同时拥有同一块堆内存：
- s1 离开作用域时释放内存。
- s2 离开作用域时又释放一次。
这就会产生 Double Free（重复释放）问题，Rust 通过 Move 机制避免了这个问题。

##  3. Copy、Move 和 Clone
Rust 中常见的三种赋值行为：
| 机制    | 含义     | 原变量能否继续使用 |
| :---- | :----: | :-------: |
| Copy  | 按位复制数据 | 可以        |
| Clone | 显式复制   | 可以        |
| Move  | 转移所有权  | 不可以       |


```rust
fn main() {
    let x = 10;
    let y = x;

    println!("x = {}", x);
    println!("y = {}", y);
}
```

这里 x 仍然可以使用，因为整数类型实现了 Copy trait。

常见 Copy 类型：
- 整数：i32、u64
- 浮点数：f32、f64
- 布尔值：bool
- 字符：char
- 由 Copy 类型组成的元组（例如 (i32, bool)）

String 默认不实现 Copy。


**理解重点：所有权解决的是数据由谁负责管理和释放的问题。**

# 二、借用（Borrowing）

如果所有权只能转移，那么一个函数想读取 String，难道每次都要转移所有权吗？

Rust 提供了借用机制。借用就是：不转移所有权，只允许其他变量或函数临时使用数据。

## 1. 不可变借用 `&T`

通过 `&` 可以创建一个引用，让其他代码访问数据，但不取得所有权。

``` rust
fn print_string(s: &String) {
    println!("{s}");
}

fn main() {
    let s = String::from("hello");

    print_string(&s);

    println!("{s}"); // ok
}
```

`print_string` 获得的是引用，而不是所有权。因此：

-   函数可以读取数据。
-   函数不会取得数据的所有权。
-   函数结束后，原来的变量仍然可以使用。

### 不可变借用规则

不可变借用有一个重要规则：**同一时刻，可以存在多个不可变引用**。

``` rust
let s = String::from("hello");

let r1 = &s;
let r2 = &s;
let r3 = &s;

println!("{r1}, {r2}, {r3}");
```
这里传递的是 s 的引用，而不是转移所有权。
它们都只能读取数据，不会修改数据，因此不会产生数据竞争。


## 2. 可变借用 `&mut T`

如果需要修改数据，就需要可变借用`&mut`。

``` rust
fn append(s: &mut String) {
    s.push_str(" world");
}

fn main() {
    let mut s = String::from("hello");

    append(&mut s);

    println!("{s}"); // hello world
}
```

注意两个地方：

``` rust
let mut s = String::from("hello");
```

这里的 `mut` 表示变量允许被修改。

``` rust
&mut s
```

这里的 `mut` 表示创建一个可变引用。

### 可变借用规则

**同一时刻，只允许存在一个有效的可变引用，并且不能同时存在其他有效引用。**

例如：

``` rust
let mut s = String::from("hello");

let r1 = &mut s;
// let r2 = &mut s; // 编译错误

r1.push_str(" world");
```

如果允许多个可变引用同时存在，可能出现一个引用正在读取数据、另一个引用同时修改数据的情况，导致数据竞争或不可预测的结果。

Rust 通过编译期检查避免这些问题。

## 3. 借用规则总结


-   可以同时有多个不可变引用。
-   可以有一个可变引用。
-   不可变引用和可变引用不能同时有效地存在。

这里的关键词是：**同时有效**。

Rust 的 NLL（Non-Lexical Lifetimes，非词法生命周期）机制：

+ **允许借用在最后一次使用后提前结束，不一定要等到变量所在的整个作用域结束**。

例如：

``` rust
let mut s = String::from("hello");

let r1 = &s;
println!("{r1}"); // r1 最后一次使用

let r2 = &mut s;
r2.push_str(" world");
```

这是允许的，因为 `r1` 已经不再使用，之后才创建 `r2`。

**理解重点：借用解决的是如何安全地访问数据，而不转移所有权的问题。**

# 三、生命周期（Lifetime）

理解生命周期，需要先理解一个问题：

**引用本身不拥有数据，那么引用指向的数据必须在引用使用期间一直有效。**

否则就会出现悬垂引用。

## 1. 什么是悬垂引用？

例如：

``` rust
fn main() {
    let r;

    {
        let s = String::from("hello");
        r = &s;
    }

    println!("{r}"); // 编译错误
}
```

这里`s` 离开内部作用域后，字符串数据被释放。但 `r`仍然试图引用它，这就产生了悬垂引用。

Rust 会在编译阶段阻止这种情况。

生命周期主要解决一个问题：引用不能比它引用的数据活得更久。

## 2. 生命周期到底是什么？

生命周期（Lifetime）可以先理解为：

**一个引用能够安全地使用的有效范围。**

例如：

``` rust
let s = String::from("hello");
{
    let r = &s;
    println!("{r}");
}
println!("{s}");
```

只要 `r` 还需要使用，`s` 就必须保持有效。

``` text
s 的有效范围：

|-----------------------|

r 的有效使用范围：

      |-----------|
```

引用的有效使用范围不能超出被引用数据的有效范围。

注意：生命周期不是运行时的计时器，也不是用来延长变量生命的机制。它主要用于编译期检查引用是否安全。

# 四、生命周期标注 `'a`

先看一个函数：

``` rust
fn longest(x: &str, y: &str) -> &str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}
```

这个函数无法通过编译。

为什么？

因为它可能返回 `x`，也可能返回`y`。编译器需要知道返回的引用究竟依赖哪个输入引用的生命周期。它无法从函数签名中确定这一点，因此需要我们明确标注。

## 1. 生命周期标注的写法

``` rust
fn longest<'a>(
    x: &'a str,
    y: &'a str
) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}
```

这里有4个 `'a`：
| 位置           | 含义                 |
| :----------- | :----------------: |
| `<'a>`       | 声明一个生命周期参数         |
| `x: &'a str` | x 的引用需要满足 `'a` 的约束 |
| `y: &'a str` | y 的引用需要满足 `'a` 的约束 |
| `-> &'a str` | 返回的引用需要满足 `'a` 的约束 |


## 2. `'a` 到底是什么？

可以把 `'a` 理解成一种**生命周期参数**。

它和泛型参数 `T` 有点类似：

``` rust
fn example<T>(x: T) -> T {
    x
}
```

这里的 `T` 是类型参数。

而：

``` rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str
```

这里的 'a 代表一个生命周期范围。

它表达的是：
- x 必须在 'a 期间有效。
- y 必须在 'a 期间有效。
- 返回的引用也必须在 'a 期间有效。

换句话说：**三个引用必须满足同一个生命周期约束。**

这里的 'a 并不是一个你提前定义好的具体时间。

它是一个约束参数，具体对应多长时间，由函数调用时的实际情况决定。

## 3. `'a` 究竟约束什么？

这是整个生命周期标注中最重要的理解点。

``` rust
fn longest<'a>(
    x: &'a str,
    y: &'a str
) -> &'a str
```

`'a` 同时约束输入引用和返回引用。

**第一：对输入引用的约束**

``` rust
x: &'a str
y: &'a str
```

表示 `x` 和 `y` 指向的数据，都必须在 `'a` 这段生命周期内有效。

**第二：对返回引用的约束**

``` rust
-> &'a str
```

表示返回的引用也只能保证在 `'a` 这段生命周期内有效，不能比 `'a`有效范围更长。


为什么输入和输出要关联起来？

因为函数可能返回 `x`，也可能返回`y`。编译器必须确保无论返回哪一个，返回引用都不会指向已经失效的数据。


**核心理解：`'a`不是只约束返回值，而是建立输入引用和返回引用之间的生命周期关系。**

## 4. `'a` 是不是要求输入引用的生命周期完全相同？

不是。

例如：

``` rust
let s1 = String::from("hello");

{
    let s2 = String::from("world!");

    let result = longest(&s1, &s2);

    println!("{result}");
}
```

`s1` 和 `s2` 的完整生命周期并不相同。`s1` 可以比 `'a` 活得更久；`s2`也可以比 `'a` 活得更久；但两者都必须在 `'a` 期间保持有效。

``` text
s1：

|--------------------------------|

s2：

       |----------------|

'a：

       |----------------|
```

如果尝试在 `s2` 失效后继续使用返回值：

``` rust
let result;

let s1 = String::from("hello");

{
    let s2 = String::from("world!");

    result = longest(&s1, &s2);
}

println!("{result}"); // 编译错误
```

就会被编译器拒绝。因为 `result` 可能引用 `s2`，但 `s2` 已经失效。

### 用一句话理解 `'a`

`'a` 是函数定义者声明的一组生命周期约束：

-   输入引用必须满足这组约束。
-   返回引用也必须满足这组约束。
-   具体能取多长的有效范围，由编译器根据实际调用情况推导。
-   调用者必须保证返回引用使用期间，其可能引用的数据仍然有效。

可以把它理解为函数和调用者之间的一份**引用安全契约**。

# 五、生命周期省略规则

并不是所有引用都需要显式标注生命周期。

Rust 有生命周期省略规则（Lifetime Elision Rules），可以自动推导一些常见情况。

例如：

``` rust
fn get(s: &str) -> &str {
    s
}
```

因为函数只有一个输入引用，编译器可以自动推导返回引用与这个输入引用关联。

它相当于：

``` rust
fn get<'a>(s: &'a str) -> &'a str {
    s
}
```

再看一个例子：

``` rust
fn longest(x: &str, y: &str) -> &str {
    // ...
}
```

这里有两个输入引用。编译器不知道返回引用应该关联 `x` 还是`y`，因此无法自动推导，需要显式标注。

生命周期省略规则中最常见的三条：

1.  每个输入引用参数会获得一个独立的生命周期参数。
2.  如果只有一个输入生命周期参数，输出引用默认使用它。
3.  如果是方法，且有 `&self` 或 `&mut self`，输出引用通常关联 `self`
    的生命周期。

**理解重点：生命周期省略不是没有生命周期，而是编译器能够自动推导时，不需要手动写出来。**

# 六、结构体中的生命周期

结构体如果持有引用，也需要考虑生命周期。

例如：

``` rust
struct User<'a> {
    name: &'a str,
}
```

这里的 `'a` 表示：`User` 结构体持有的 `name` 引用，必须在 `'a`期间保持有效。

例如：

``` rust
fn main() {
    let name = String::from("Tom");

    let user = User {
        name: &name,
    };

    println!("{}", user.name);
}
```

``` text
name 的有效范围：

|-----------------------|

user.name 的引用范围：

      |-------------|
```

如果 `name` 先失效，而 `user`还试图使用它，就会产生悬垂引用，因此编译器会阻止这种情况。

**理解重点：只要结构体保存了引用，就必须确保被引用的数据至少在结构体使用引用期间有效。**

# 七、特殊生命周期 `'static`

`'static` 是 Rust 中一个特殊的生命周期。

它表示引用在整个程序运行期间都有效。

例如：

``` rust
let s: &'static str = "hello";
```

字符串字面量存储在程序的静态内存区域，因此可以拥有 `'static` 生命周期。

但需要注意：

``` rust
T: 'static
```

并不意味着一个值一定要活到程序结束。

它表示类型 `T` 不包含短于 `'static` 的借用引用。

例如：

``` rust
fn example<T: 'static>(value: T) {
    // ...
}

example(String::from("hello"));
```

`String` 可以满足 `'static`约束，因为它拥有自己的数据，不依赖外部短生命周期的引用。

**理解重点：`'static`表示生命周期约束，不等于变量必须一直存活到程序结束。**

# 八、三个机制之间的关系

到这里，可以把所有权、借用和生命周期串起来理解。

## 1. 所有权：管理数据

每个值都有明确的所有者，由所有者负责管理和释放数据。

``` text
Owner
  │
  ▼
 Data
```

## 2. 借用：访问数据

通过引用访问数据，不必转移所有权。

``` text
Owner
  │
  ▼
 Data
  ▲
  │
Reference
```

## 3. 生命周期：保证引用安全

确保引用使用期间，被引用的数据始终有效。

``` text
Reference 的有效范围
          │
          ▼
必须处于 Data 的有效范围内
```


------------------------------------------------------------------------

# 九、最后记住这 6 句话

1.  **所有权**：每个值都有一个所有者，所有者负责管理数据。
2.  **Move**：所有权转移后，原变量不能再使用该值。
3.  **借用**：通过 `&T` 或 `&mut T` 使用数据，而不取得所有权。
4.  **借用规则**：多个不可变引用可以共存，但不能与有效的可变引用同时存在。
5.  **生命周期**：引用使用期间，被引用的数据必须保持有效。
6.  **生命周期标注**：通过 `'a`声明引用之间的有效性约束，让编译器检查引用是否安全。

最重要的是建立这条思维链：

**所有权解决数据管理，借用解决数据访问，生命周期解决引用有效性。**
