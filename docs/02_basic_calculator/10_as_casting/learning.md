# As casting：显式整数转换与位模式

[对应源码](../../../exercises/02_basic_calculator/10_as_casting/src/lib.rs)

## 显式转换与目标类型推断

**Rust 不会隐式转换不同整数类型，需要明确选择转换。** 相比 C/C++ 的隐式数值转换，这让可能改变数值含义的操作出现在代码中。

```rust
let a: u32 = 10;
let b = a as u64;
let c: u64 = a as _;
```

`as` 后面是目标类型；`_` 让编译器根据上下文推断，这里由 `c: u64` 确定。

## 转换不会检查是否保留原值

这里的整数 `as` 转换不会因为目标类型装不下而在运行时失败，**但这不意味着转换后数值不变**。

| 转换情形 | 规则 | 示例 |
|---|---|---|
| 位数增加 | 无符号源补零，有符号源扩展符号位 | `47u16 as u32` 为 `47` |
| 位数减少 | 保留目标宽度的低位，丢弃高位 | `256u16 as u8` 为 `0` |
| 位数相同，改变有无符号 | 保留位模式，按目标类型解释 | `255u8 as i8` 为 `-1` |
| 布尔转整数 | `false` 为 0，`true` 为 1 | `true as u8` 为 `1` |

**不能只凭“目标类型位数更大”判断保值。** 例如 `-1i8 as u16` 是 `65535`，从有符号负数转为无符号数改变了数值含义。应确认源值在目标类型的可表示范围内。

## 字面量越界与截断不同

本题的 `255 as i8` 中，未加后缀的 `255` 会被推断为 `i8`，字面量本身超出范围，因此默认触发 `overflowing_literals` 诊断。题目用 `#[allow(overflowing_literals)]` 有意允许它。

这不是“编译器会阻止所有已知会截断的 `as` 转换”。明确写出源类型的 `256u16 as u8` 可以编译，结果为 `0`。

## 同样的位如何表示正负数

Rust 的固定宽度有符号整数使用补码。对于 8 位整数，最高位权重是 `-128`，其余位权重为 `64、32、16、8、4、2、1`。

因此 `1111_1111` 按 `u8` 解释是 `255`，按 `i8` 解释是 `-128 + 127 = -1`。转换保留了位，改变了对位的解释。
