# Rust 复习笔记

将零散的学习注释整理成简体中文复习文档：概念清楚、重点突出、按知识关系组织，便于快速回忆。学习者 Rust 零基础，已掌握 C/C++ 和 Go。

## 整理流程

1. **确定范围**：按用户指定的练习或源码定位。未指定时，结合当前对话确定；无法确定则询问具体练习。只处理选定练习。
2. **提取知识点**：读取该练习源码和已有笔记，以学习者补充的注释为主，结合相关代码理解含义。原有课程说明只用于理解上下文，不逐段搬入笔记。没有学习注释的练习保留原状。
3. **组织知识关系**：把注释拆成知识点，合并重复结论，按概念的先后依赖分组。例如先解释模块与作用域，再解释 `use` 和路径；同一概念的定义、规则与易错点放在一起。
4. **写入对应文档**：将 `exercises/<章节>/<练习>/src/...rs` 的学习内容归入 `docs/<章节>/<练习>/learning.md`。同一练习的多个源码文件合并整理到一份笔记。保留已有独立知识点和源码链接，更新重复或错误内容。
5. **逐项复核**：确认每个注释知识点都有准确的归属、每段内容都服务于复习、链接有效；结束时简要报告更新的文档及实质纠错。

## 内容取舍

- **先给结论，再给必要解释**：用一句话说明概念，再写规则；术语首次出现时就近解释。简洁以读懂为前提。
- **围绕注释体系化**：以概念命名小节，展示知识点之间的关系；组织顺序由知识依赖决定，不照抄源码行序或问答顺序。
- **范围由学习标注决定**：每条内容应能追溯到学习注释、已有笔记，或理解它们所必需的前置概念。无关知识、后续章节预习、课程套话与操作过程留在文档之外。
- **突出少量重点**：用 **加粗** 标记关键规则和容易记反的区别；语法、类型和命令使用行内代码。避免整段加粗。
- **示例只解释难点**：文字不足以说明时，选用最短代码片段；同一规则保留一个足够说明问题的例子，省略整份源码和无关测试代码。
- **对比说明设计原因**：涉及与 C++ 不同的设计时，就近简述“差异 → Rust 为什么这样设计 → 使用上的影响”。仅在帮助理解当前知识点时对比 Go。
- **准确优先于照录**：结合代码校正注释中的误解，明确区分语法规则、常见约定与简化理解。仅补充影响当前结论的边界；无法确认的关键事实先核实，不写成确定结论。
- **直接编辑目标文档**：源码和学习注释保持原样；已有笔记合并更新，重复运行不追加重复章节。

## 文档形态

使用一个主题标题、对应源码链接，以及若干按概念命名的小节。每节通常采用“概念一句话 + 核心规则 + 必要示例或易错点”，按内容需要取舍，不填充空模板。

知识点确有映射或区别时使用小表格；其他内容优先短段落或平级列表。避免为每个小节固定增加总结、原理和对比等重复栏目。

笔记中的源码链接相对于文档文件所在目录计算，例如：

```markdown
# Welcome：引用、返回值与单元测试

[对应源码](../../../exercises/01_intro/00_welcome/src/lib.rs)

## 引用与生命周期

……
```

## 完成标准

- 所选范围中学习者标注的独立知识点均已覆盖，已有有效笔记得到保留。
- 概念依赖顺序清楚，重复知识点只保留一处完整说明。
- 关键结论醒目，Rust 新概念无需依赖未解释的术语才能读懂。
- 每段都服务于当前练习的复习，源码、测试与其他练习未被修改。
